# /style-write 流程（按你的风格生成文章）

> **目的**：深度对话挖掘用户真实想法 → 加载档案 + 检索样本 → 组装风格 prompt → 生成草稿 + 风格报告。

## 触发后第一件事

读 `~/.claude/styles/weights.json` 判断状态：
- 🔴 冷启动（0-2 样本）→ 转 `${CLAUDE_SKILL_DIR}/prompts/cold_start.md`
- 🟠 萌芽（3-9）→ 继续，但风格置信度低
- 🟡/🟢 → 正常流程

状态检查通过后，进入 Phase 1 深度对话挖掘。

## Phase 1：深度对话挖掘

> **宗旨**：每当用户表达一次自己的主观意见时，至少提出一个问题用于深入探讨这个话题。
> 目的不是收集参数，而是理解用户**真正想表达什么**——这样才能写到"像你"。

### 规则总览

| 规则 | 内容 |
|------|------|
| **逐层提问** | 一次只问一个问题，不做信息轰炸 |
| **动机优先** | Q1 固定问主题，Q2 开始重点挖掘"为什么写" |
| **跟随主观意见** | 用户每表达一次主观意见 → 至少追问 1 个深入问题 |
| **零压力** | 每个问题末尾标注"（可以不回答，说'跳过'就行）" |
| **上限保护** | 最多 8 个问题，到达后自动进入 Step 1 |
| **随时终止** | 用户说"开始写吧"/"够了"/"可以写了"/"生成吧"→ 立即进入 Step 1 |

### 主观意见的识别信号

当用户表达以下内容时，视为"主观意见"，必须追问：
- "我觉得..." / "我认为..." / "我感觉..."
- "最触动我的是..." / "最让我难受的是..."
- "这个事让我意识到..."
- 用户给出具体案例/故事/场景
- 用户用了情绪化表达（"真的很烦" / "太爽了" / "搞不懂为什么"）

### 追问方向（按优先级）

| 优先级 | 方向 | 示例 |
|--------|------|------|
| 1 | **深挖动机** | "为什么这个点最触动你？" |
| 2 | **追问观点** | "那你觉得根本原因是什么？" |
| 3 | **追问细节** | "当时具体发生了什么？你第一反应是什么？" |
| 4 | **追问变化** | "这件事之后，你的想法/做法有变化吗？" |
| 5 | **追问对比** | "跟以前相比，你现在怎么看这件事？" |
| 6 | **追问反例** | "有没有相反的经历？或者你身边有人跟你看法不同吗？" |

**追问质量要求**：
- 问题必须基于用户刚说的内容，不能是模板化问题
- 要有"往下挖一层"的感觉，不能停留在表面
- 避免"你还有什么想说的吗"这类空洞问题

### Q1（固定）：主题

```
✍️ 这次想写什么？

一句话、几个关键词、或者一个你想探讨的问题都行。

（可以不回答，直接说"跳过"——我会用通用模式写）
```

### Q2（固定）：动机

```
💭 为什么想写这个？

比如：
- 最近发生了什么事让你有感而发？
- 你想通过这篇文章表达什么？
- 还是单纯想记录一下？

（可以不回答，说"跳过"就行）
```

### Q3-Qn（动态）：跟随主观意见

根据用户的回答，识别主观意见信号，选择一个追问方向深入提问。

**每个问题末尾必须带**：`（可以不回答，说"跳过"就行）`

### 终止条件

| 触发 | 行为 |
|------|------|
| 用户说"开始写吧"/"够了"/"可以写了"/"生成吧" | 立即进入"确认写作参数" |
| 问题数达到 8 个 | 告知用户"聊了 8 轮了，我先开始写"，进入"确认写作参数" |
| 用户连续 2 次说"跳过" | 判断用户不想深入，进入"确认写作参数" |
| 用户回答内容已足够丰富（3+ 个具体案例/观点） | 可问"要不要开始写了？"确认后进入"确认写作参数" |

### 对话结束后：整理"观点摘要"

将挖掘到的内容整理为结构化摘要，供 Step 4 的 prompt 注入：

```
📋 观点摘要（来自深度对话）
- 核心观点：{1-3 条}
- 具体案例：{用户分享的场景/经历，保留原话关键词}
- 情感基调：{克制/愤怒/释然/困惑/自嘲/...}
- 用户原话摘录：{2-3 句最有代表性的原话}
- 写作动机：{一句话总结}
```

### 确认写作参数（强制，不可跳过）

> ⚠️ 深度对话结束后，**必须先确认写作参数**，再进入 Phase 2。不能跳过这一步直接生成。

**三个必问项**：

```
✍️ 聊得很清楚了，最后确认三件事：

1️⃣ 文体
   - 散文体（默认，场景陈述+观点递进）
   - 对话体（两人问答形式）
   - 其他（你说）

2️⃣ 平台
   - 朋友圈（100-300字）
   - 小红书（300-800字）
   - 即刻（300-800字）
   - 公众号（800-1500字）

3️⃣ 调性（可选）
   - 克制 / 锋利 / 温柔 / 自嘲 / 冷幽默
   - 不指定就用档案默认

（不回答的话，默认：散文体 + 朋友圈短篇 + 档案默认调性）
```

**用户回答后**，整理为参数供 Step 4 使用：

```
📋 写作参数
- 文体：{散文体/对话体}
- 平台：{平台名}
- 字数：{目标字数范围}
- 调性：{默认/用户指定}
```

**如果用户提及了调性要求**（如"不要太丧"/"温和一些"），保留到 Step 4 的 prompt `{调性要求}` 中。

## Phase 2：遍历「终版 + 作者偏好」知识库（自主进化）

> 🧬 **自主进化**：每次生成前必须回顾两样东西——用户亲手定稿的**终版原文**，和逐字对比出来的**作者偏好**。
> ⚠️ **这一阶段不可跳过**。跳过 = 上次改稿白改，用户会在同一个地方改第二遍。

### 两个来源，各教什么

| 来源 | 路径 | 教 AI 什么 |
|------|------|-----------|
| **终版原文** | `results/终版/` | "用户最终认可的成品长什么样"——初版被改过之后的正确答案 |
| **作者偏好** | `difference/` | "初版错在哪、用户为什么这么改"——精确到措辞层级的偏好规则 |

> `samples/positive/` 教的是"用户怎么写"（目标）；
> `results/终版/` 教的是"什么样的成品能过关"（已达成的答案）；
> `difference/` 教的是"AI 惯犯的错误"（避坑清单）——**三者互补，缺一不可**。

### Step 2-A：检索终版原文

1. **列出所有终版**：
   ```bash
   ls ~/.claude/skills/style-distiller/style-write/results/终版/
   ```
   文件名格式：`result-{MMDD}_{中文标题}-终版.md`，其中 `result-{MMDD}` 是这篇文章的唯一 id。

2. **对每篇终版**：
   - `Read` 文件内容，判断是否有 YAML frontmatter（`---` 开头）
   - **有 frontmatter**：提取 `topic`、`style_confidence`、`verification`
   - **无 frontmatter**（纯文本）：视为"用户亲手定稿的成功案例"，全部纳入检索
     - 从文件名的 `{中文标题}` 段提取主题关键词（如 `result-0503_我和父亲-终版.md` → 主题 = 亲情/家庭/父亲）
     - 从正文前 3 段提取内容摘要，辅助判断主题匹配度
     - 默认 `style_confidence = 0.85`（用户亲手定稿，可信度高于 AI 自评）
   - 计算综合分：`主题匹配度 × 0.4 + 风格置信度 × 0.4 + 时间衰减 × 0.2`
     - 无 frontmatter 的文章，时间衰减从文件修改时间读取
   - 挑出 top 3

3. **输出检索报告**：
   ```
   🔍 自主进化检索 · 终版知识库（共 {N} 篇）
     1. result-0503_我和父亲 - 0.91 (主题 0.95 + 置信度 0.85 + 时间 0.95)
     2. result-0507_越己再悦己 - 0.85 (主题 0.90 + 置信度 0.85 + 时间 0.80)
     3. result-0628_想清楚，再行动 - 0.78 (主题 0.85 + 置信度 0.85 + 时间 0.65)
     主题相关文章：{N} 篇
   ```

4. **提取特征签名**（同 retrieval.md 格式），供后续验证：
   - 对每篇挑中的终版，提取 7 维特征签名（hook / 节奏 / 口气 / 金句 / 收尾 / 词汇 / 格式）
   - 这些签名用于 Step 4 的 prompt 和 Step 5.5 的验证

### Step 2-B：加载作者偏好（difference/）

> ⚠️ **全部加载，不做筛选**。difference 里的每一条偏好都是用户真金白银改出来的，
> 无论主题是否相关，"怎么措辞"的偏好都是跨主题通用的。

1. **列出所有差异文件**：
   ```bash
   ls ~/.claude/skills/style-distiller/style-write/difference/
   ```
   文件名格式：`result-{MMDD}_差异对比.md`，`result-{MMDD}` 对应初版/终版的同一个 id。

2. **`Read` 每一个差异文件**，提取两部分：
   - **「表达偏好总结」表格**里的每一条偏好 → 汇总成"作者偏好清单"
   - **「逐字差异分析」**里的具体改写对照 → 作为反面案例（"别这么写，要那么写"）

3. **合并去重**：多个差异文件里重复出现的偏好，标注出现次数——出现次数越多，约束越硬。

4. **输出偏好报告**：
   ```
   🧬 作者偏好加载（difference/ 共 {N} 份差异对比）
     ├ 累计偏好条目：{M} 条
     ├ 高频偏好（出现 ≥2 次）：{列出，这些将作为 🚨 硬约束}
     └ 单次偏好：{列出，作为 🟡 强约束}
   ```

5. **注入优先级**：
   | 出现次数 | 注入层级 | 说明 |
   |---------|---------|------|
   | ≥ 2 次 | 🚨 硬约束 | 用户反复改同一个毛病，违反 = 本次生成失败 |
   | 1 次 | 🟡 强约束 | 必须遵守 |

### 兜底

| 情况 | 行为 |
|------|------|
| `results/终版/` 为空 | 跳过 Step 2-A，提示"终版知识库为空（首次使用）" |
| `difference/` 为空 | 跳过 Step 2-B，提示"暂无作者偏好记录，改完稿后可让我做终版对比" |
| 两者都为空 | 直接进入 Step 1 |

```
🔍 自主进化检索：终版知识库为空（首次使用）
   本次生成后将存入 results/初版/，你改完稿放进 results/终版/，
   再让我做一次终版对比，下次即可自主进化。
```

### Step 2：检索最相关的 3-5 个样本（双路召回）

> ⚠️ **这一步决定训练会不会白费**。挑错样本 = LLM 学不到典型特征 = 风格还原失败。

**严格按 `~/.claude/skills/style-distiller/style-lib/prompts/retrieval.md` 的多路召回策略执行**（含终版知识库作为新召回路径）。

**三路召回**：
- **路 A（samples/）**：用户喂入的正样本 → 教 AI "用户怎么写"
- **路 B（results/终版/）**：用户亲手定稿的终版 → 教 AI "什么样的成品能过关"（已在 Phase 2-A 完成检索，此处直接引用结果）
- **路 C（difference/）**：作者偏好清单 → 教 AI "别再犯这些措辞上的错"（已在 Phase 2-B 完成加载，此处直接引用结果）

`Bash` 列出所有正样本：
```bash
ls ~/.claude/styles/samples/positive/
```

对每个候选样本：
1. `Read` 它的 frontmatter 提取主题、维度、备注
2. 计算综合分（主题 0.5 + 维度 0.3 + 时效 0.2）
3. 挑出 top 3-5

**生成检索报告**（让用户看到挑了哪些）：
```
🔍 检索报告
  1. #012 - 0.92 (主题 0.95 + 维度 0.80 + 时效 0.95)
  2. #023 - 0.87 (主题 0.90 + 维度 0.75 + 时效 0.90)
  3. #005 - 0.83 (主题 0.85 + 维度 0.85 + 时效 0.78)
  主题相关样本：3/50（覆盖度 6%，建议补样本）
```

**关键样本的特征提取**（用于后续验证）：
对每个挑中的样本，提取 7 维特征签名（hook 类型、节奏、口气、金句、收尾、词汇、格式），后续生成后逐项核对。

### Step 3：检查反样本

`Bash` 列出反样本：
```bash
ls -la ~/.claude/styles/samples/negative/ | head -20
```

如果存在反样本，`Read` 它们的反特征清单，**组装到 prompt 时主动避开**。

### Step 4：组装风格 prompt（分层硬约束）

> ⚠️ **这是另一个决定训练白不白费的关键节点**。档案翻译成"软描述"等于白搭。

**Prompt 必须分层**——核心约束用 🚨 标记 + 重复，软约束给范围，参考样本嵌入原文。

```markdown
你是一个**风格严格的写作者**。本次任务的"风格"权重 > "内容"权重。
如果风格不达标，内容再好也不算成功。

用我提供的"风格档案"，写一篇关于「{主题}」的{长度}字文章，用于{平台}。
{调性要求}

> ⚠️ 注意：下方"📝 主题素材"中包含了用户的真实观点、案例和原话。**必须将这些内容融入文章**，而不是写一篇只有风格没有内容的空壳文章。

## 核心观点
{从对话中提取的用户明确观点，1-3 条}

## 具体案例
{用户分享的具体经历/场景，保留原文关键句子}

## 情感基调
{从对话中感知到的情绪——克制/愤怒/释然/困惑/自嘲/...}

## 用户的原话
{摘录 2-3 句用户最有代表性的原话，用于保持语感}
> "{原话1}"
> "{原话2}"

## 写作动机
{用户为什么想写这篇文章，一句话总结}

═══════════════════════════════════════
# ✅ 输出要求
═══════════════════════════════════════

1. 严格遵守硬约束（禁用词/句式/反特征）
2. 满足强约束（钩子/口气/收尾）
3. 尽量符合软约束（节奏/金句/词汇/格式）
4. 用上至少 3 个样本的核心特征
5. 字数 {目标} ±20%
6. 输出文章正文 + 自报家门（用了哪些样本特征）
```

### Step 5：生成草稿

将组装好的 prompt 作为 LLM 上下文的一部分，生成草稿。

**生成时的特殊指令**：
- 让 LLM 在生成时**显式标记**用了哪些档案特征（自报家门）
- 让 LLM 给出 3 个微调方向
- 不要过度使用档案里的特征——风格是"用得自然"，不是"处处用"
- **必须融入"📝 主题素材"中的用户观点和案例**——这是用户通过深度对话表达的真实想法，不是可选的装饰

### Step 5.5：⚠️ 强制质量验证（不能跳过）

> **LLM 容易"嘴硬"自报做对了，必须独立验证**。

**严格按 `~/.claude/skills/style-distiller/style-lib/prompts/verify.md` 流程执行**：

1. **7 维硬约束核对**（钩子/节奏/口气/金句/收尾/词汇/格式）
2. **反样本规避扫描**（扫描所有禁用词/禁用句式）
3. **作者偏好核对**（🆕 逐条核对 Phase 2-B 加载的偏好清单，高频项违反任意一条 = 直接判定 `rewrite_required`）
4. **样本特征还原核对**（挑中的样本特征是否真的用上了）
5. **主题完成度检查**
6. **计算偏离度评分**

**根据偏离度处理**：
- 0-10%：🟢 直接进入 Step 6
- 10-25%：🟡 自动修正后进入 Step 6
- 25-50%：🟠 标注问题段，建议重写
- > 50%：🔴 **必须重写**（最多 2 次），仍不行则告知用户"档案需要补充"

### Step 6：后处理

#### 6.1 字数校准
检查字数：
- 短文 < 80 字 → "太短了，要不要扩写？"
- 短文 > 200 字 → "超出预期，要不要精简？"

#### 6.2 风格违规检查
逐项检查 prompt 里的"避免"清单是否被违反：
- ❌ 用了禁用词？→ 提醒用户并提供替换
- ❌ 用了反样本的写法？→ 重写该句

#### 6.3 双写存档（drafts/ + results/初版/）（含质量报告）

**双写规则**：

| 验证结果 | drafts/ | results/初版/ | 说明 |
|---------|---------|--------------|------|
| `passed` | ✅ 写入 | ✅ 写入 | 通过验证的文章进入初版区，等待用户微调 |
| `auto_fixed` | ✅ 写入 | ✅ 写入 | 自动修正后也纳入 |
| `rewrite_required` | ✅ 写入 | ❌ 不写入 | 偏离过大，不纳入 |

**写入 drafts/**（保持原逻辑）：
`~/.claude/styles/drafts/{YYYY-MM-DD}_{NNN}_{slug}.md`

##### 🚨 写入 results/初版/ —— 文件名规范（强制，不可自由发挥）

```
~/.claude/skills/style-distiller/style-write/results/初版/result-{MMDD}_{中文标题}-初版.md
```

| 字段 | 规则 | 示例 |
|------|------|------|
| `result-{MMDD}` | **当日日期**，4 位，月日各补零。这是这篇文章的**唯一 id** | `result-0820` |
| `{中文标题}` | 文章的中文标题，**用中文，不用拼音、不用英文 slug、不用序号** | `在等一个最好的状态` |
| `-初版` | 固定后缀，标识这是 AI 生成的初版 | `-初版` |

**完整示例**：
```
result-0820_在等一个最好的状态-初版.md
result-0503_我和父亲-初版.md
result-0628_想清楚，再行动；遇困难，先思考-初版.md
```

**取当日日期**：
```bash
date +%m%d
```

**唯一 id 的作用**：`result-{MMDD}` 是贯穿三个目录的关联键——
```
results/初版/result-0820_中文标题-初版.md     ← AI 生成
results/终版/result-0820_中文标题-终版.md     ← 用户微调后手动放入
difference/result-0820_差异对比.md            ← 逐字对比产物
```
三者靠 `result-0820` 这个 id 对应。**初版和终版的中文标题应保持一致**（用户改标题的话以终版为准）。

**同一天生成多篇怎么办**：
如果 `results/初版/` 下已存在同 `result-{MMDD}` 的文件，且中文标题不同 → 正常写入（id 相同但标题不同，靠标题区分）。
如果连中文标题也完全相同 → 在 id 后加字母后缀：`result-0820b_中文标题-初版.md`。

**写入前必须确认目录存在**：
```bash
mkdir -p ~/.claude/skills/style-distiller/style-write/results/初版
```

## 风格置信度算法

```
置信度 = (
  总样本量 / 30 × 0.4
  + 弱维度样本数 / 10 × 0.3
  + 主题匹配度 × 0.2
  + 反样本数 × 0.1
) capped at 1.0
```

可视化：
- 0.0-0.2：🔴 几乎通用
- 0.2-0.5：🟠 有点感觉
- 0.5-0.8：🟡 比较像
- 0.8-1.0：🟢 很像你

## 边界情况

### 1. 用户 Q1 跳过主题
- 用通用模式生成，但强提示"没有主题信息，生成结果会偏泛泛"
- 建议用户："下次可以简单说一句想写什么，效果会好很多"

### 2. 用户给的主题档案里没相关样本
- 用通用生成 + 强提示"档案里没有这个主题的样本，生成结果会偏通用"
- 建议用户："要不要先 /style-feed 喂一篇类似主题的文章？"

### 3. 用户连续 /style-write 5 次主题都不同
- 提醒："你的档案在不同主题上覆盖不均，要不要 /style-review 看看该补哪个？"

### 4. 用户要求改稿
- 把"改稿"路由到 `/style-feedback`（如果是对自己写的改）
- 或把"改稿"路由到 `/style-write` 的变体（如果是改 AI 生成的）

### 5. 用户想要"反风格"——故意不写自己
- 在主题里加 `{调性: 反风格 / 故意不像我}`
- 生成时弱化档案约束，只取硬禁忌（反样本）规避
